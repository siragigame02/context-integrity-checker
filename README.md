# Context Integrity Checker

**日本語の制約保持を検査するローカルCLI / MCPツール — 検査LLM呼び出し0、合成評価で変質50/50件・自然文12/13件を検出（v0.1.2）。**

AIが会話や作業履歴を要約した後、禁止事項・承認状態・日数などの明示的な保護事項が変わっていないか確認するPythonソフトウェアです。AIエージェントを運用する開発者・組織を対象に、シラギ / Siragiが開発しています。初期対象は日本の利用者です。

## What it does

Context Integrity Checker validates explicitly supplied Japanese constraints after context compaction or summarization. It runs locally and returns JSON evidence for missing constraints, contradictions, weakened or strengthened conditions, preservation, and unsupported cases. The checker makes zero LLM calls; it does not summarize text or guarantee general semantic preservation. English documentation does not imply English-input support.

## 機能と使い方

1. 利用者が原文、要約後テキスト、保持したい制約と原文中の引用位置を用意します。
2. `verify_context` をCLI・Pythonライブラリ・任意のローカルMCPアダプターから呼び出します。
3. 利用者側でJSON結果を確認し、問題・保留に対処します。結果は操作の実行許可ではありません。

| 検査対象 | 例 |
| --- | --- |
| 禁止・許可の反転 | 「削除操作は禁止」→「削除操作が可能」 |
| 承認・決定状態 | 「本番反映は未承認」→「本番反映は承認済み」 |
| 固定日数と最短日数 | 「工程Aの7日後」→「工程Aの7日以降」 |
| 明示的な例外 | 対応文法内の例外の追加・除去 |
| 欠落 | 対応文法の要約から保護事項がなくなる |

`propose_missing_restoration` は欠落した原文引用を追加して再検査した候補を返します。矛盾・条件変化・保留には適用せず、自動で文章を書き換えません。

## 実行例：固定日が最短日数に変わった場合

- 原文：`工程Bは工程Aの7日後に実施。`
- 要約：`工程Bは工程Aの7日以降に実施。`
- 実測判定：`constraint_weakened`（条件の緩和）

完全なJSONは [入力例](example-request.json) と [実測出力](example-result.json) を参照してください。架空の合成データをv0.1.2のCLIで実行した例です。入力位置はUnicodeコードポイントの0起点・終端非包含です。

## 合成評価と限界

| 評価セット | 変質の検出 | 保持への誤警報 | 保留 |
| --- | --- | --- | --- |
| 限定文法100件 | 50/50件 | 0/25件 | 曖昧25/25件 |
| 自然文を含む診断30件 | 12/13件 | 0/10件 | 全体13/30件 |

測定対象はエンジン0.1.2、測定日は2026-10-10です。いずれも実装担当と同じ作成者による合成例で、独立した評価や実顧客の精度実績ではありません。自然文の未検出1件は保留です。上記の検出件数は一般文章の正解率ではありません。集計は [機械可読の商品情報](product-info.json) にも収録しています。

通常の長い自由文では保留が多くなります。未対応の文が要約内にある場合、全保護事項を保留にする場合があります。原文からの保護事項の自動抽出、原文の真偽、保護事項以外の意味、未知の追加情報は検査しません。`confidence` は未校正のためnullです。

## トークンと費用の判断材料

検査コア自体のLLM呼び出し・推論トークン消費は0です。要約生成、結果のLLMへの送信、再評価には別途費用がかかり得ます。

合成の制約3件を手作業で短くした例では、o200k_base / tiktoken 0.14.0で原文32トークン、短縮候補27トークン、候補と詳細検査JSONを合わせると472トークンでした。製品が圧縮した結果ではありません。

同じ候補を100回使用し、詳細検査結果をLLMへ送らない場合、原文を100回送る場合に比べて入力500トークン少ないという条件付き試算です。要約生成費・再評価費・製品価格・キャッシュ差は別途考慮が必要です。同じ短縮候補を既に使っている運用に検査器を追加するだけでは、直接の入力節約は0です。実運用の総費用削減は未検証です。

## 動作環境・データ

- Python 3.10以上。確認環境：Windows / Python 3.10.6。他のOS・Python版は未検証です。
- コアCLIはPython標準ライブラリのみ。入力はUTF-8 JSON、64 KiB以下、保護事項1～50件です。
- 任意MCPはstdio接続、追加依存 `mcp==2.3.0`。公式SDKクライアントとの7テストを確認済みです。特定AIホストとの接続・自動購入は未検証です。
- 検査コアはネットワーク・APIキーを必要とせず、顧客の原文を販売者へ送信しません。実行環境と計算資源は購入者側が用意します。
- 結果には原文引用が含まれます。MCPホスト等による保存・LLM送信は利用者の設定によります。
